PawTrace: identifying individual dogs from photographs

Most animal-vision models answer "what breed is this dog?" PawTrace answers a harder question: "is this the same dog?" It fine-tunes a ResNet-101 with metric learning so that two photographs of one animal land close together in feature space, and two look-alikes do not. The result is a search engine for lost dogs, shipped as a live, read-only demo.

Overview

Lost-dog matching is a retrieval problem, not a classification one. A per-dog classifier would need retraining every time a dog is registered, and most dogs have only a handful of photos. I used metric learning instead, training an embedding where distance means similarity, so new dogs need no retraining at all. The difficulty is that one dog looks very different between photographs while two unrelated retrievers can look nearly identical, so anything leaning on breed or general appearance confidently returns the wrong animal.

The decision that shaped everything else was initialising from a dog-breed classifier rather than generic ImageNet weights. The backbone already understood dog anatomy and coats — but a breed classifier is trained to treat two dogs of one breed as the same thing, actively suppressing the individual detail this task depends on. Those starting weights were both a head start and an obstacle, and most of the training effort went into reshaping the deep layers where that breed-invariance was baked in.

Data

No single public dataset covers this task, so training data came from three: DogFaceNet for face identities, MPDD for full bodies in varied poses, and YT-BB-Dog for body identities at scale. Splits are identity-level — every photo of a dog lands in one split, since splitting by image would test the model on dogs it had already memorised. After cleaning: 3,355 dogs / 17,593 images for training, 419 dogs / 2,176 images held out.

Shortcut risk, and where it bites. Every YT-BB image of a given dog comes from one video, so background is constant within an identity and a model can score well by learning the scene rather than the dog. It is also 64% of the held-out test set — 270 of 419 dogs — so it shapes the reported numbers, not just training. Results below measures exactly how much.

Training

ResNet-101 producing a 2,048-dimension L2-normalised embedding per image, trained with batch-hard triplet loss. Each batch is sampled as 16 identities × 4 photos, and for every anchor the loss takes the hardest positive and hardest negative available: random triplets are solved immediately and yield no gradient, so learning only happens on the hard cases. Face and body images are balanced 50/50 so neither domain dominates, and a variance penalty tightens each identity’s cluster, which triplet loss alone leaves loose.

Results

Measured on 419 held-out dogs (2,176 photos) using the standard re-ID protocol: every image queries all the others, excluded from its own gallery.

Top-10 is the product metric — the job is to cut thousands of records down to a shortlist a human scans in seconds, not to be infallible on the first guess. Fine-tuning lifted face Rank-1 from 84.3% to 91.2%, and full-body from 67.6% to 93.3% (body mAP 0.484 → 0.813). That asymmetry is what vindicates the initialisation choice: faces carry dense detail that survives a breed-oriented encoder, bodies did not, and at 67.6% the pre-trained model was largely reporting “these are both spaniels.”

System architecture

FastAPI and SQLAlchemy over SQLite, serving a React + TypeScript frontend from the same origin, packaged as a single Docker image on Hugging Face Spaces. The scoring rule is the design decision worth naming: a dog’s match score is the maximum cosine similarity across all (query photo × candidate photo) pairs, so one weak photo cannot drag down an identity that also matches strongly, and every extra angle can only help. Embeddings are stored tagged with model version so vectors from different generations are never compared, and the demo’s read-only behaviour is enforced by server middleware rather than by hiding UI controls. Making it work on phones meant normalising images client-side before upload, and making it fit its host meant profiling the process to ~551 MB against a 512 MB limit.
