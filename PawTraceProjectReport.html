PawTrace: identifying individual dogs from photographs

Most animal-vision models answer "what breed is this dog?" PawTrace answers a harder question: "is this the same dog?" It fine-tunes a ResNet-101 with metric learning so that two photographs of one animal land close together in feature space, and two look-alikes do not. The result is a search engine for lost dogs, shipped as a live, read-only demo.

Overview

Lost-dog matching is a retrieval problem, not a classification one. A per-dog classifier is a non-starter in production: every newly registered dog would add a class and require retraining, and most dogs have only a handful of photos. I used metric learning instead, training an embedding where distance means similarity, so new dogs need no retraining at all.

The hard part is that one dog looks very different between photographs (angle, lighting, pose), while two unrelated retrievers can look nearly identical. Any system leaning on breed or general appearance confidently returns the wrong animal.

Key decisions

  • Initialised from a dog-breed classifier rather than generic ImageNet weights. The backbone already knew dog anatomy and coats. The catch: a breed classifier is trained to treat two dogs of one breed as the same thing, actively suppressing the individual detail this task needs. The starting weights are both a head start and an obstacle.
  • Unfroze the last 2 of 4 ResNet stages. Early layers (edges, textures) are generic and worth keeping; the deep layers are where breed-invariance was baked in, so those are what needed reshaping.
  • Selected checkpoints on mAP, not Rank-1. Rank-1 is noisy between epochs. mAP considers where all of a dog’s photos rank, making it both stabler and a better proxy for the real objective.

Data

No single public dataset covers this task, so training data was assembled from three, each covering a gap in the others.

SourceContributesWeakness
DogFaceNetDog faces, many identities, varied conditionsAligned crops, little background variety
MPDDFull bodies, multiple poses and locationsSmall; often one session per dog
YT-BB-DogBody identities at scaleFrames from a single video per dog

Shortcut risk identified and mitigated. Every YT-BB image of a given dog comes from one video, so background is constant within an identity. A model can score well by learning the scene instead of the dog. I used it for training scale but never as the measure of success, and excluded it entirely when selecting demo examples.

  • Identity-level splits, not image-level. All photos of a dog land in exactly one split. Splitting by image would test the model on dogs it had memorised.
  • Cleaning pipeline: de-duplicated near-identical frames (which make training trivial and evaluation optimistic), removed corrupt images, and quarantined identity folders containing more than one animal.

Training

ResNet-101 producing a 2,048-dimension L2-normalised embedding per image, trained with batch-hard triplet loss. Batches are PK-sampled (16 identities × 4 photos); for each anchor the loss selects the hardest positive and hardest negative, then separates them by a 0.45 margin. Training on hard examples is what produces gradient at all; random triplets are solved immediately.

  • Intra-identity variance penalty (weight 0.5) — triplet loss only constrains relative distance, permitting loose clusters. This tightens each identity.
  • 50/50 face/body batches so neither domain dominates the gradient.
  • Random-crop augmentation (50% chance, 40–85% of frame) attacks the face/body framing gap, so the model learns scale invariance instead of two separate visual regimes.
  • Early stopping on patience 30 against a 1,000-epoch ceiling, keeping only the best checkpoint.

Diagnostic caught early: a run ended with a flat curve that initially read as a data ceiling. It had actually hit a wall-clock timeout and was still improving. Treating an infrastructure limit as a modelling conclusion would have misdirected the next several experiments.

Top-10 is the product metric. The system’s job is to reduce thousands of records to a shortlist a human scans in seconds, not to be infallible on the first guess. mAP sits well below Rank-1 because ranking all of a dog’s photos highly is much harder than surfacing one.

The asymmetry confirms the breed-invariance hypothesis. Faces carry dense detail that survives a breed-oriented encoder; bodies did not, and at 67.6% the pre-trained model was largely reporting “these are both spaniels.” Body mAP nearly doubled (0.484 → 0.813). The training bought its value precisely where the starting weights were weakest.

System architecture

FastAPI backend with SQLAlchemy over SQLite, serving a React + TypeScript frontend from the same origin, packaged as a single Docker image on Hugging Face Spaces.

  • Model versioning: Embeddings are stored tagged with model name and version so vectors from different model generations are never compared, preventing silent index corruption.
  • Dog-level aggregate scoring: Overall match score uses max cosine similarity across all (query photo × candidate photo) pairs. One low-quality photo cannot drag down an identity that also has strong matches.
  • Modular search interface: Embedder, storage, and vector index sit behind clean abstract interfaces. Exact brute-force cosine search is used for current scale, with ANN indexing ready as a drop-in swap.
  • Server-side demo guardrails: Read-only behavior is enforced by server middleware rejecting all write methods rather than relying on hidden UI controls.

Engineering decisions & edge cases

Rejected a feature after testing it

The breed classifier returned “Pomeranian, 100%” for random noise, a page of text, and a blank square, while real Pomeranians scored 40–64%. With 120 classes and no “none of these” option, softmax must elect a winner, and out-of-distribution inputs often win by a landslide. I tested a confidence threshold to flag non-dog images: it cannot work, because crisp photos of genuine Pomeranians score 99.85%, indistinguishable from noise. Rather than ship a filter that tells owners their real dog may not be a dog, the interface states the limitation.

Caught a contaminated benchmark

The breed model scored 91.2% top-1 on the standard Stanford Dogs split, higher than its own model card claims, which signals train/test overlap rather than success. On a clean holdout it scored 80.7% top-1 / 98.0% top-10. The conservative figure is the one reported, and the interface qualifies it by image quality.

Built the demo to avoid flattering itself

Selecting demo examples by score alone produced near-duplicate photos matching at 96%, technically true and practically meaningless. Selecting the most visually distinct photo instead produced unusable images (dogs facing away, mid-bite). The working rule: the most distinct photo that still ranks its own twin first with a solid score. Demo scores landed at 70–90% rather than the high 90s, which is the honest picture.

Mobile Safari & HEIC upload failures

Uploads initially failed on mobile devices due to unhandled HEIC formats and large camera payloads (~25 MB). Fixed by implementing client-side normalization in JavaScript (decoding, downscaling to 1024px max edge, JPEG compression) prior to upload. This bypassed browser MIME-type issues, reduced upload payloads by ~95%, and drastically improved mobile reliability, with server-side HEIC conversion added as a fallback.

Deployment & infrastructure diagnostics

  • Memory footprint optimization: Resolved container memory crashes by profiling model runtime overhead (~551 MB resident) against 512 MB platform limits, converting an ambiguous slowdown into a specific memory allocation decision.
  • SQLite WAL persistence: Fixed a deployment issue where SQLite Write-Ahead Logging (WAL) session changes were omitted from container snapshots by implementing explicit database checkpoints prior to deployment commits.

Future Architecture & Next Steps

  • Open-set confidence gating: Develop an out-of-distribution detection mechanism to reject non-canine images prior to embedding generation.
  • Cross-condition benchmark dataset: Curate evaluation sets featuring the same dogs across varied cameras, lighting conditions, and dates to stress-test real-world performance.
  • Approximate Nearest Neighbor (ANN) index: Integrate FAISS or ScaNN as database size expands toward 100k+ candidate vectors.
  • Threshold calibration: Calibrate similarity scores to establish probability bounds, enabling automated alert notifications instead of manual review.
