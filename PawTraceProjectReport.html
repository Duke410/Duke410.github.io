PawTrace: identifying individual dogs from photographs

PawTrace is a search engine for lost dogs that finds them based on their photos: upload an image, and it ranks a database of found dogs by how closely each one matches that specific dog. Two pipelines share a ResNet-101 backbone, a breed classification pipeline to narrow down the pool, and an image similarity search, fine-tuned with metric learning to tell individuals apart rather than breeds. The system is currently deployed as a live, read-only demo with breed and location filtering disabled.

Overview

When I came up with the idea for this project, I decided that I would need to compare dogs using image embeddings rather than simply trying to classify them. So every time a picture is uploaded, it goes through a model to determine the dog in the picture's estimated breed and another model that turns it into an embedding, which is a list of numbers describing that image. This embedding keeps track of all the different features of the dog in the image, such as fur color, snout length, or body size, and it gets stored in the database alongside the dog it belongs to. When someone searches the database with a new dog, the system compares the embeddings for its photos against all of the stored dogs' embeddings and scores how similar they are. This way, each image only needs to be run through the models one time.

An added layer of difficulty comes from the fact that the same dog can look completely different between two photos depending on the angle, the lighting, and the pose, while two unrelated dogs can look nearly identical. Because of this, anything that leans too heavily on breed or general appearance was going to confidently return the wrong dog.

This was a risk I knew about going in, so I spent some time trying to mitigate it. I found CNN models that were very good at telling breeds apart, but not quite as good at telling two individual dogs of one breed apart, which is the case that matters here. However, I thought breed-specific information might be useful for re-identification, so I decided to use a breed classification model as a base for the dog re-identification model. I ended up training only the last level of the classification model, so that it would retain as much breed information as possible before being fine tuned using metric learning to recognize individual dogs using triplet loss. In this way, I was able to make it so that the distance between two embeddings actually reflects whether they show the same dog.

Data

No single public dataset covered what I needed, so I put the training set together from three of them. DogFaceNet gave me a large number of face identities, Multi Pose Dog Dataset (MPDD) gave me full body shots of the same dogs in different poses, and YT-BB-Dog gave me body identities at a much larger scale. After cleaning out corrupt files, near duplicate frames, and folders that turned out to contain more than one dog, I was left with 3,355 dogs and 17,593 images for training and 419 dogs and 2,176 images held out for testing.

One catch worth being upfront about is that every image of a given dog in the YT-BB-Dog dataset comes from a single video, so the background stays the same across all of that dog's photos. Additionally, the images in DogFaceNet and MPDD were often taken multiple in a row, so their backgrounds tended to be similar for a given dog as well. This meant the model can score well by learning the scene instead of learning the dog.

I did try to measure and account for this. There is a public camera trap dataset called the Sibetan dog dataset that photographs the same dogs across multiple days and cameras, which is exactly the cross background test I wanted, and I set it aside as a separate evaluation set from the start. However, in the end, it could not tell me anything useful because the dog images it contained had a median size of about 81 by 75 pixels, while the model takes a 224 by 224 input. This meant that the images in that dataset were just not high-quality enough to use for evaluation, and I could find no other dog re-identification datasets with explicitly different baground images.

Training

The model started as a ResNet-101 model fine tuned for dog breed classification that outputs a 2,048 dimension embedding for each image. Images are normalized so that comparing two of them is just a matter of taking the cosine similarity between the two embeddings. I trained it further using batch-hard triplet loss, which samples each batch as 16 different dogs with 4 photos each, and then for every image in that batch picks out the hardest positive, meaning the photo of the same dog that looks least similar to it, and the hardest negative, meaning the photo of a different dog that looks most similar to it. The reason for doing it this way is that randomly chosen triplets are almost always solved immediately and produce no gradient at all, so the model really only learns from the difficult cases. I also balanced faces and bodies 50/50 within each batch so that neither one dominated the training.

Results

To measure how well this worked I used the standard re-identification protocol on the 419 held-out test dogs, where every image in turn is used as a query against all of the other images, with the query's own image excluded from the results it is scored against.

Face90.9%97.0%98.8%65.0%
Body93.3%97.1%98.1%66.4%
Combined92.4%97.0%98.2%65.6%

Rank-1, top 5, and top 10 all ask whether the right dog showed up somewhere near the front of the results. mAP, which stands for mean average precision, asks a harder question: it looks at where every other photo of that dog landed in the ranking, not just the best one. A dog with one strong match and four weak ones can score a perfect rank-1 and still have a lower mAP, which is why the mAP column sits so far below the others.

The number I pay the most attention to is top 10 rather than rank 1, because the point of the system is to cut a database of thousands of dogs down to a shortlist that a person can look through in a few seconds, not to be right on the very first guess.

In the end, fine-tuning made a large difference, and it made a much larger difference for bodies than it did for faces. Face rank-1 went from 84.3% to 91.2%, while full body went from 67.6% to 93.3%, and body mAP went from 48.4% to 81.3%. I think that gap is the clearest evidence that starting from a breed classifier was both a help and a problem. Faces have enough fine detail that a breed-focused encoder still keeps track of individual dogs reasonably well, but bodies do not, and at 67.6% the pre-trained model was basically just reporting that two dogs are both the same breed.

System architecture

The backend for this project is built on FastAPI with SQLAlchemy over SQLite, serving a React and TypeScript frontend from the same origin, and the whole thing is packaged as a single Docker image running on Hugging Face Spaces.
